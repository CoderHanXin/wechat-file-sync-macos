# 最小桌面应用与部署（M5 / M6）

日期：2026-11-19。M4 基线：`3c0fb73`；M5 分支：`codex/menu-bar-settings`。用户授权继续后续设计开发，小范围选择自行决定并记录，重大范围／数据策略另行确认。测试不操作真实微信、配置或登录项。

## 已确认身份和范围

用户确认本机从未安装原版，采用独立标识 `io.github.coderhanxin.wechat-file-sync`。不自动读取原作者应用容器；不做旧版导入界面，不搬动既有归档。原有核心迁移回归仍保留。

菜单栏与引擎同一进程，关闭设置窗口继续运行，退出等待当前串行动作结束后释放写锁。不增加辅助守护进程、KeepAlive、任务中心或数据库服务。一个设置窗口提供账号、目录、只读默认、暂停和必要授权／恢复。

## 本轮采用的小范围选择

- 使用系统 AppKit，沿用 Command Line Tools 和脚本构建，不增加完整 Xcode 或第三方 UI 依赖。
- `ApplicationSession` 保存统一状态连接和写锁；扫描和配置均由桌面 worker 的单个串行队列处理，主线程只做窗口、选择和确认。
- 运行状态显示本次扫描或授权错误，单账号失败不掩盖其他账号；数据库错误停止扫描，不把“进程在运行”显示为同步全部正常。
- 首次未配置时打开设置；已有配置启动时留在菜单栏，点击“设置”或重新打开应用可显示窗口，避免登录时弹窗。
- 可自定义初始管理根目录；尚无账号记录或未完成配置时允许重新选根目录；已有账号后只提供原目录重新授权。不悄悄搬迁现有归档；跨根／跨盘迁移如有实际需求再设计。
- 已有实体批量权限和诊断命令继续作为低频 CLI；不为每条命令制作按钮。
- 手动恢复在一个简单对话框中选失联实体及副本，显示逐来源差异与选择；执行仍调用 M4 的同一服务。
- 登录启动默认不开启，用户在设置中显式开启。采用 macOS 13+ 的 `SMAppService.mainApp`，真实状态为待批准时提示系统设置。关闭应用不注销登录启动，也不在本次会话自动重启。
- 独立容器中当前配置路径使用 Application Support 下 `WeChatFileSync/state.sqlite`，CLI 与菜单栏共享；M6 已将构建文件和安装脚本统一为 WeChatFileSync。

## 实施及验收

M5 接入菜单栏、设置窗口、串行会话和恢复对话框；临时数据库覆盖写锁、配置后的账号意图和故障隔离。单独编译的 `DESKTOP_TESTING` 窗口夹具只生成假账号，不启动桌面 worker，不操作安全书签或登录项，检查控件状态、布局边界和关闭／重新打开。

M6 已收敛为一个安装路径、一个登录启动机制；安装与配置分开，升级先确认应用已退出，复制并验证后替换，保留状态。卸载先停止应用并取消登录启动，只移除应用，不删除归档、微信链接或状态。脚本测试使用临时 HOME、假应用及命令替身，不能运行真实安装脚本。

参考：[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)、[退出延迟及完成回调](https://developer.apple.com/documentation/appkit/nsapplication/reply%28toapplicationshouldterminate%3A%29)。登录启动不提供崩溃 KeepAlive 的保证。

真实微信旧消息、真实沙盒授权、实际登录／注销／升级，以及 macOS 13 和 Intel 实机留待用户明确允许后验收。不能将模拟脚本、普通命令行窗口或 Rosetta 自测等同于这些真实结果。本轮可以完成实现、隔离验证和发行候选包，不能声称真实环境全部验收通过。

## 专项复核补充（2026-11-19）

读库失败不再显示缓存中的正常状态，停止扫描并禁用依赖旧状态的操作；成功读到新快照后才能更新可用状态。空配置重新选根目录只是首次设置纠错，不增加归档迁移。安装回滚按实际目录身份核对，不依赖改名后尚未来得及更新的变量；升级和卸载仍要求先退出应用。
