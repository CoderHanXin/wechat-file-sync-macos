# 微信文件同步需求与行为规则

更新日期：2026-11-18。实现基线：`e2061d4`。本文描述后续改造，功能状态见各表。

## 当前机制

现有程序一次绑定一个微信账号，监视其 `msg/file` 目录。启用前的普通文件进入历史基线；启用后的新文件在大小和修改时间稳定约 15 秒后，被移动到系统下载目录，微信原位置替换成符号链接。

下载文件平铺保存，不按账号或月份归档；同名文件通过附加序号避让，没有内容去重。程序跟踪下载目录内的改名和移动；文件移出下载目录或被删除后，移除对应微信链接。从废纸篓恢复文件后，现有版本不会自动恢复关联。

这套机制通常只有一份实际内容。维护微信链接不等于额外备份，也不包含从微信服务器重新下载文件的能力。

## 已确认的需求变更

| 编号 | 需求 | 行为与边界 |
| --- | --- | --- |
| R01 | 相同内容合并展示 | 相同内容在去重范围内保存一份实际文件；相同文件名不代表内容相同。具体去重范围见待决定事项 D01。 |
| R02 | 保留多条微信来源 | 同一份实际文件可以对应多个微信源路径，各来源都能关联到该文件。来源指程序实际发现的账号及文件路径，不承诺识别发送者或群聊。 |
| R03 | 尊重用户删除实际文件 | 删除共享实体后，允许其全部微信关联失效，并提供后续恢复关联的途径。文件内容能否恢复取决于是否还有可访问副本，关联记录本身不能恢复内容。 |
| R04 | 微信侧清理不删除归档 | 微信源路径或链接被清理后，已经保存的实际文件继续保留，不自动反向删除。 |
| R05 | 同步文件只读保护 | 从微信同步的实际文件默认设置只读，设置中允许关闭。普通只读权限用于防止直接误写，不承诺所有软件都强制另存。 |
| R06 | 编辑交给系统与编辑器 | 用户通过编辑器另存，或自行复制及调整权限；本工具不提供创建可编辑副本、文件编辑和版本管理功能。 |

删除后移除微信链接，仅代表本工具管理的本地访问路径失效。能否在微信重新下载、能否从其他设备或备份获得文件，应分别验证，不把“本地关联失效”写成“永久无法找回”。

## 规划范围

以下来自前期讨论，作为开发计划的目标范围；具体方案仍需在对应阶段细化。

| 编号 | 目标 | 建议行为 |
| --- | --- | --- |
| P01 | 多账号同时同步 | 手动添加多个微信账号，每个账号有独立授权、历史基线、状态和暂停开关。 |
| P02 | 不同账号分目录归档 | 默认保存到 `下载/微信文件/<账号备注>/`，不同账号的同名文件互不干扰。内部账号身份不使用可变的备注。 |
| P03 | 持续维护移动后的关联 | 建议在整个下载目录内追踪改名和移动，文件归属仍由源账号决定。移出管理范围的行为见 D03。 |
| P04 | 原生配置界面 | 菜单栏提供状态与入口；配置窗口管理账号、权限、暂停恢复和错误处理。无需文件浏览器。 |
| P05 | 标准应用安装与升级 | 逐步转为应用启动后配置，配置操作与重新安装分离；替换应用时保留状态并执行版本迁移。 |
| P06 | 独立任务与故障隔离 | 一个文件异常不阻塞其他文件，一个账号不可用不阻塞其他账号。 |
| P07 | 降低重复扫描和写盘 | 下载目录索引在同一轮任务间共享；批量变更合并写入，并保留可靠的恢复记录。 |

## 典型场景

### 同一内容多次接收

同一内容在微信目录形成 A、B、C 三个源文件。完成去重后，只展示一份实际文件，并维护三条来源到该文件的链接。删除该实体会影响三条关联；用户后续恢复内容时，应能恢复仍然适用的来源关联。

如果两个文件名称相同、内容不同，应分别保留。名称不同而内容相同的文件，也应按内容判断，并保留各自的原始名称和来源路径。

### 用户整理文件

建议新文件按源账号进入独立文件夹；之后用户可以在下载目录内按项目归类。归类不改变文件的源账号和已有微信来源，不因为移动到另一个账号文件夹就重新认定归属。

### 用户编辑文件

只读保护引导用户通过外部编辑器另存。普通只读权限无法完全阻止在可写目录中用新文件替换原路径。关闭保护、手动调整权限或外部替换后，程序必须重新核对实际内容，不凭旧摘要把新接收的原件关联到已经修改的文件。

需要说明：关闭保护后，直接编辑共享实体会影响其所有微信入口。R05 不提供不可变备份保证，也不要求通过隐藏副本维持该保证。

## 保留的基本约束

- 继续以移动和符号链接为首版方案；改为纯复制或额外原件库需要单独变更需求。
- 目标是整理微信已下载到本机的普通文件，不控制微信服务器下载，不修改聊天数据库。
- 新添加账号独立建立历史基线，旧文件批量导入不与持续同步混在一起。
- 初期沿用同文件系统移动的约束；跨文件系统保存需要另行设计复制校验与恢复流程。
- 实际文件可能被用户删除或外部修改，应用应报告真实状态，不把进程存活等同于同步正常。

## 暂不纳入

- 创建可编辑副本、文件编辑、文档版本管理。
- 为维持微信访问而暗中保留被用户删除内容的完整副本。
- 自动识别微信昵称、发送者或群聊。
- 自动下载微信历史附件、历史文件批量迁移、跨平台或云端同步。
- 文件浏览器、复杂统计和自动更新。
- 首版跨账号合并内容；最终范围以 D01 的决定为准。
