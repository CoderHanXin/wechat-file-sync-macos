# 删除与关联恢复实施方案（M4）

日期：2026-11-19。基线：M3 `ce7d43c`；分支：`codex/file-association-recovery`。简化核心、命令和最小 v4 已实现，尚未发布；实际临时样本验证见 [验收记录](validation-report.md)。行为依据见 [已确认决定 C10 至 C14](decisions/0004-file-association-recovery.md)。

## 目标：两条恢复路径

| 场景 | 行为 |
| --- | --- |
| 根目录内正常改名、移动 | 沿用已有身份跟踪并维护链接。 |
| 原文件失联后以原身份回到根目录 | 自动恢复此前由本程序因失联清理的链接，无需手动选择。 |
| 找回的是不同身份的副本 | 用户指定文件，查看预览后确认恢复。 |
| 再次收到相同内容的新文件 | 正常接纳，不仅凭摘要自动恢复旧关联；可由用户选为恢复副本。 |
| 微信侧自行清理来源、原因不明或同路径被新生命周期使用 | 不自动重建；手动恢复也不覆盖新对象或复活已复用的旧来源。 |

不备份文件内容、不找回已删除字节、不遍历废纸篓、不读取聊天数据库、不跨账号共享、不创建微信目录层级。候选在根目录外时由用户自行放回。历史记录清理暂缓，不自动过期。

## 最小必要数据变化

M3 已有实体身份、来源生命周期、原名、原接收摘要、实体当前摘要和操作日志。主要缺口是无法可靠区分“程序因失联清理”与“外部移除”，以及链接清理与保存状态之间的中断窗口。

M4 只补充：

- 来源结束原因：程序因实体失联清理、外部消失／复用、原因不明。只有第一类进入自动恢复候选；路径复用会使旧候选失效。
- 清理／恢复操作类型及必要前提：账号、来源、实体、预期对象身份与目标、操作阶段。优先复用现有操作存储，不建设第二套任务框架。
- 如手动恢复需重绑来源，允许事务更新当前实体关联；原名、原接收身份与摘要保持原义，不建立完整历次绑定或内容版本表。

当前实体摘要仍只是去重缓存，变化后可以失效。手动恢复优先使用已有的来源原接收摘要辅助核对；未知保持未知，不为恢复额外建设最后关联版本证据系统。

不同身份的副本使用新实体记录，或复用已有同账号实体，不覆盖旧实体身份。同一来源恢复沿用来源 ID；同路径新接收仍是新来源 ID。重绑前相关 M3 操作必须结束，继续满足账号和操作外键约束。保留旧失联实体记录，不借机清理它。

预计需要 SQLite v4，最终字段和表变更在实现时以最小需求确定；版本号只用于防止旧程序误写新语义。迁移前生成 0600 的一致备份，在单事务中转换并校验，失败回到可读 v3。保留账号、基线、书签、暂停／移除状态和所有 M3 在途操作、权限及链接目标信息。迁移不访问微信、不移动、chmod 或恢复文件。

M3 `missing` 可保守迁为“旧版记录为程序因失联清理”，实时检查通过后才允许自动恢复；`detached` 原因不明，不猜测。未知字段不补造。JSON／v1／v2 仍按已提交阶段升级，不重放过期授权。

## 自动恢复

1. 根和源授权及身份有效时，按既有方式核对文件；访问或枚举失败只报错，不能判作删除并批量清理链接。
2. 实体在范围内确实找不到时，先保存逐来源清理意图，再条件移除属于本工具的链接，完成后记录原因。unlink 后提交失败能按操作日志继续核对。
3. 对仍有自动恢复候选的失联实体，以固定内部间隔批量复查身份，复用本轮根目录索引；不承诺瞬时恢复，不额外增加监听服务或用户调优选项。
4. 原身份返回后，逐来源检查路径没有新生命周期、源父目录仍存在且可访问、源路径为空或仍是已知旧链接，再记录恢复意图并建立链接。
5. 占用、授权失败或在途操作阻塞时保留原因，不覆盖其他对象。成功项成为正常活动来源；失败项可继续重试。暂停账号仍维护已有关系，已移除账号不访问源。

微信侧已删除的来源、来源原因不明或原路径曾被新生命周期复用，均不因原文件返回而自动恢复。程序无法证明的旧对象不自动接管。

原身份返回不等于内容未变：若内容已修改，沿用 M3 的摘要失效和当前内容核对，不把编辑后的文件按旧摘要去重，也不替用户恢复原内容。

## 手动指定与预览

M4 先提供基础命令，M5 加入同一功能的简单界面，不建设文件浏览器。流程只有“选择失联记录 → 指定根目录内文件 → 预览 → 确认”。来源默认是因该实体失联而由程序清理的记录；原因未知的旧失联记录可由用户明确选择，标示未知；已知微信侧自行清理或路径已复用的来源跳过。

| 预览内容 | 要求 |
| --- | --- |
| 原记录 | 所属账号、原文件名、最后归档位置、已知大小及来源数量；不存在的信息显示未知。 |
| 候选 | 当前名称、位置、大小、已有摘要匹配／不匹配／无法核对。摘要不是恢复授权的门槛。 |
| 影响 | 将哪些来源指向所选文件，哪些会跳过以及原因；必要时允许取消某条来源。 |
| 差异 | 摘要不一致时明确说明关联内容将改变；缺摘要说明无法确认与原内容相同，再由用户确认。 |

不展示未经掌握的联系人、群聊或精确接收时间。用户可自行在系统中查看文件；本工具不增加编辑、预览器或版本管理。

仅接受授权根目录内的普通文件，禁止越界父目录、未知符号链接、跨账号物理文件共享及不安全硬链接。未管理的文件只有在用户显式指定后才可登记，保留当前名称、位置与权限。不同身份不继承旧文件的写位恢复记录，也不因登记为实体就自动施加只读。

手动确认允许用户重新关联内容，但不能绕过文件安全检查。源路径被占用或存在新生命周期时跳过，即使内容相同；父目录缺失时不重建。选中的目标在确认或执行期间发生变化时停止相关动作并要求重新查看预览。

## 执行与中断恢复

复用 SQLite 单写入通道及操作日志，自动和手动恢复使用同一套逐来源执行逻辑。M4 写入型命令要求先停止后台；同一次操作中计算预览并确认，不存储独立、长期有效的预览计划，不增加计划 ID 管理命令。取消预览不改变关联或生成待执行任务。

最小恢复过程：先持久化执行意图和对象前提，再安全安装链接，复核后事务提交当前关联并结束操作。临时对象如有必要，必须记录可核对的归属；不能仅凭文件名前缀或链接目标字符串删除或接管对象。安装后提交失败能通过日志和对象身份补齐；未知变化保持冲突。仅持久化了已确认执行的任务才可在后台继续。

多个来源逐条处理，部分成功时如实报告，不实现跨全部来源的文件系统事务。重复执行不新增来源生命周期，不重复安装或覆盖。数据库失败停止后续文件动作；恢复不移动、合并或删除候选文件，也不创建内容备份。

所有文件、数据库、授权和服务替身只在随机临时目录生成，不操作真实微信文件、本机真实配置、登录项或系统废纸篓。文档轮次只检查链接及内容一致性，不运行功能测试。真实微信历史入口、沙盒授权、实机与掉电验收仍需另行确认范围。

## 本轮落实

v4 沿用既有表，增加可选来源原因和恢复操作字段，不新增版本、审计或预览计划表。链接清理与恢复由 `LinkRecovery` 共用现有日志；清理先排他移到记录的临时位置，核对实际对象再移除，遇到替换内容归还或保留现场，手动预览无写入；内部身份复查间隔为 30 秒，测试可注入为 0。候选确认后变化会取消能证明归属的准备链接，保留内容与来源记录；数据库提交失败保留任务继续核对。

当前命令为 `--restore-links ACCOUNT ENTITY --file /绝对路径`，同一次调用中预览、选择来源并输入 RESTORE。低频未知旧记录允许用户显式指定；已知外部移除或路径复用跳过。不提供历史记录清理。
