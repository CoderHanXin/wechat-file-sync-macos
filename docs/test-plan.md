# 微信文件同步测试与验收计划

更新日期：2026-11-19。本文件定义后续改造的验收，不表示计划中的功能或测试已经完成。需求依据见 [需求与行为规则](requirements.md)。

## 现有验证基线

讨论阶段基于 `e2061d4` 完成过通用包构建、ARM64 自测、x86_64 经 Rosetta 自测，以及安装卸载脚本的隔离模拟测试。正常流程通过不代表真实微信、沙盒授权和所有异常情况均已覆盖。

另外使用临时测试程序复现过：目标改名后旧名被其他内容占用会误关联；源链接消失且目标改名会阻塞扫描；源链接被新普通文件替换后会漏同步。后两项具有源链接丢失或被替换的共同前提，未确认微信会主动执行该清理。批量删除 30 个目标时测到同一轮完整扫描下载目录 30 次、重写状态 30 次。

M1 已把这些行为纳入 `Tests/SyncCoreTests/` 的正式回归，实际结果见 [验收记录](validation-report.md)。后续计划中的测试仍不等于已执行。

M2 的具体账号隔离、暂停、目录、迁移和配置中断场景见 [多账号实施方案](multi-account-plan.md) 中 A01 至 A18。本轮已落为多账号、迁移、配置恢复和命令测试，结果见验收记录；测试继续只用随机临时目录、假授权和命令替身，不操作真实微信文件或本机真实配置。

M3 的 B01 至 B26 场景见 [内容去重与只读实施方案](content-dedup-readonly-plan.md)，保留 M2 的 86 项回归并计划新增 v3 夹具。本轮已实现 v3 夹具并执行新增用例，实际结果见验收记录；原 86 项仍保留。所有文件样本、数据库、ACL 和扩展属性均在随机临时目录生成。

M3 专项复核后已提交 `ce7d43c`，实际基线为 134 项回归。M4 的 F01 至 F15、阶段注入和范围约束见 [删除与关联恢复实施方案](file-association-recovery-plan.md)。本轮已实现两条恢复路径，并执行相关临时样本回归；实际覆盖见验收记录。全部样本在临时目录创建，不访问真实微信、本机配置或登录项。

## 中断与资源故障

在关键阶段注入退出或失败：记录操作计划后、移动实体后、建立链接前后、接入重复来源前后、移除重复实体前后、权限修改后、配置注册前后、存储提交失败时。

恢复后需验证三件事：仍有正确的文件内容可访问；文件与来源关系能与实际状态核对；重复执行不会覆盖其他文件或生成多份无主实体。

另覆盖磁盘空间不足、只读或不可访问的目录、状态文件损坏、权限变化和应用重新启动。涉及真实掉电耐久性的结论需要专门验证，不能由原子写入接口直接推导。

## M4 专项验收重点（计划）

- 访问／枚举失败不判作删除；链接清理先保存意图，覆盖 unlink 后提交失败。
- 原身份返回自动恢复程序清理的来源；微信侧清理、原因不明或路径已复用不自动重建。
- 副本预览展示账号、原名、位置、大小、摘要结果与影响；缺摘要或不匹配时明确告知，由用户确认。
- 确认前后目标变化、源占用、跨账号和越界不能因用户确认绕过；取消预览不产生执行任务。
- 安装和提交中断可重试；复用现有操作日志，不增加长期预览计划或历史清理测试。
- v3 到最小 v4 保留全部在途操作及权限证据；新身份不继承旧写位恢复记录，迁移失败可读 v3。

完整预期见 F01 至 F15。本轮最终核心回归 156 项通过，134 项是 M3 历史基线；具体结果见验收记录。

## 真实微信与桌面验收

| 场景 | 要观察的行为 |
| --- | --- |
| 正常接收与多次转发 | 内容是否确实形成多个源文件；去重后各个微信入口是否能打开同一原件。 |
| 下载暂停、续传与重新下载 | 稳定判断和只读施加时机是否影响写入；是否出现不完整内容或额外副本。 |
| 从微信打开只读文件 | 常用编辑器实际如何提示；微信预览和打开是否受影响。 |
| 用户改名、归类、删除与恢复 | 微信入口、程序状态和实际文件是否与规则一致。 |
| 微信清理、切换账号与退出 | 明确观察到的真实行为，不预设微信会删除符号链接。 |
| 重启应用、注销登录与重启系统 | 登录启动、授权书签、暂停设置和恢复记录是否保留。 |
| 应用沙盒授权 | 首次授权、重新授权、书签过期及移动后的访问是否符合范围。 |

真实测试前确定账号、目录和允许操作的样本文件；使用可替换的样本，不用重要文件试验破坏性场景。涉及微信自身是否重新下载的结论，按实际版本记录。

## 构建部署与迁移验收

- 在声明支持的系统和架构上分别构建、运行；Rosetta 结果不代替 Intel 实机结果。
- 区分命令行编译的临时测试程序与签名沙盒应用，分别执行检查。
- 验证应用安装、首次配置、登录启动开关、关闭窗口、退出和卸载。
- 若采用单进程登录启动，记录其与原 KeepAlive 的差异；若采用内置服务，验证注销注册、状态展示和停止语义。
- 替换升级后不丢账号、来源和内容索引；旧格式无法迁移时保留原数据并给出恢复方式。
- 验证旧服务已停用，同一源目录只有一个处理者；按 D10 验证旧版导入。
- 本机构建验证临时签名与权限。正式分发时另验证 Developer ID 签名、公证和下载后的首次启动体验。
