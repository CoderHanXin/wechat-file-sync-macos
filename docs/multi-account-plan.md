# 多账号同步实施方案

日期：2026-11-18。代码基线：`9b29fbf`。分支：`codex/multi-account-sync`。状态：六项行为已确认，M2 已实现并进行本地验收，尚未发布。

M2 将 M1 的单账号引擎扩展为多个账号独立管理，共用一个可配置管理根目录和一个后台进程。新文件进入各账号的独立子目录，已有文件在整个管理根目录内继续跟踪。M2 不实现内容去重、只读策略或完整设置界面。

## 已确认的行为

M0 继续生效；本轮六项已确认，原始决定见 [多账号配置与暂停行为](decisions/0002-multi-account-configuration.md)。

| 事项 | 已确认规则 |
| --- | --- |
| 管理根目录 | 用户可自定义，下载目录仅为默认建议，核心不依赖固定目录名称。 |
| 文件归属 | 由源账号决定，在管理范围内改名或移动不改变归属。 |
| C01 配置修改 | M2 先停止后台再写配置，不增加运行中修改配置的进程通信。 |
| C02 暂停 | 只停止接纳新增文件，已有链接与在途操作继续维护。 |
| C03 修改备注 | 只改显示名称，不自动改名归档目录或移动文件。 |
| 测试与分支 | 使用隔离临时样本，开发分支按实际功能命名。 |

## 本轮追加确认

以下推荐方案已由用户确认，作为实施依据。

| 编号 | 事项 | 推荐方案 | 另一种选择及影响 |
| --- | --- | --- | --- |
| C04 | 移除与再次添加账号 | 保留实体、链接、基线和历史记录，清除本工具保存的源书签并停止管理；以后通过显式恢复并重新授权复用原账号 ID。 | 直接删除账号记录会使以后难以恢复原关联和历史基线。彻底清理应另设操作。 |
| C05 | M1 升级后的文件位置 | 原文件和现有链接不搬动；迁移为一个“原账号”，后续新文件进入该账号的独立子目录。 | 把已有文件一起归类需要额外的批量搬移、链接更新和中断恢复，不放入普通格式升级。 |

## M2 范围

首版沿用一个共享的可配置管理根目录，每个账号绑定独立源目录与归档子目录。根目录在线切换、每账号不同管理根目录、目录批量迁移和图形设置仍在后续范围。

```text
<管理根目录>/
└── 微信文件/
    ├── 个人微信/
    └── 工作微信/
```

每个账号独立保存授权、历史基线、同步记录和新增同步开关。M2 不改变“只处理启用后新文件”的基本策略，不读取聊天数据库，不自动获取昵称、发送者或群聊。

文件名避让仅在新文件的账号归档目录内进行。两账号收到同名文件分别保存；相同内容在 M2 仍可能有多份，账号内去重由 M3 实现。

## 当前实现需要改变的边界

| M1 现状 | M2 调整 |
| --- | --- |
| 配置和书签只有一行，固定 `id = 1`。 | 管理根目录与账号分开存储，源书签按账号保存。 |
| `baseline`、`transfers` 只按源相对路径作为主键。 | 使用账号 ID 与源相对路径的复合主键，避免同路径跨账号冲突。 |
| `SQLiteStateStore.save` 会比较完整快照，并删除快照中不存在的记录。 | 引入按账号限定的存储适配器，账号 A 的保存只能读写 A 的记录，不能删除 B 的数据。 |
| `SyncWorker` 使用 `managedRoot` 同时选择新文件位置和查找移动文件。 | 增加独立初始归档目录；已有目标始终记录相对整个管理根目录的路径。 |
| 同步扫描同时执行已有记录维护和新文件接纳。 | 分离维护与接纳，使暂停只影响后者，在途恢复继续执行。 |
| 目录索引在单个 worker 的一轮内部缓存。 | 调度器提供轮次级共享索引，同一根目录供所有账号复用。 |
| 一个授权失败会在进入唯一 worker 前退出。 | 每账号独立解析源授权并报告状态，其他有效账号继续运行。 |

以上变化尤其要覆盖目标重名后的重新选址、planned 恢复和旧记录路径，不能只修改第一次移动的目标。

## 数据模型与 SQLite 迁移

建议数据库结构升级为 `user_version = 2`，仍使用系统 SQLite，不引入网络依赖。

| 对象 | 主要信息与约束 |
| --- | --- |
| `managed_roots` | 根目录 ID、路径、身份、授权书签。M2 只配置一个实际根目录。 |
| `accounts` | UUID、根目录 ID、备注、源路径与身份、源书签、初始归档相对目录与身份、新增开关、移除状态。 |
| `baseline` | 主键为 `(account_id, relative)`，保存各账号启用前的文件身份。 |
| `transfers` | 主键为 `(account_id, relative)`，保存阶段、实体身份、根目录相对目标、临时名称和观察快照。 |
| `account_operations` | 账号添加及归档目录准备的持久化阶段，用于处理 SQLite 事务之外的文件夹创建与改名。 |

账号 ID 不使用备注、微信昵称或可变路径。活跃账号不能重复绑定同一源目录身份；路径与身份一起检查，处理别名、大小写和目录重建。身份唯一性应依据规范化字段，不比较 JSON BLOB 的原始字节顺序。

建议外键约束使用显式启用与完整性检查，账号移除采用状态变更，避免级联清除历史。SQLite 中外键需要按连接启用，应在事务开始前完成。[SQLite 外键说明](https://www.sqlite.org/foreignkeys.html)

迁移顺序为：

1. 后台已停止，写入命令或正常启动取得原有进程锁；只读查询不触发迁移。
2. 校验版本和数据完整性，使用 SQLite 备份 API 保存一致的 v1 快照，备份失败则不继续。
3. 在一个事务内建立 v2 表，将旧配置映射为共享根目录与一个账号，原样迁移基线、同步阶段和书签。
4. 旧 `destination` 继续相对原管理根目录解释，不在字符串前机械添加新账号目录。
5. 校验记录数量、身份、相对路径和外键；最后更新版本并提交。失败则回滚，v1 仍可读取。
6. 新账号归档目录在授权有效后按配置操作流程准备；旧实体和链接的迁移本身不做文件搬动。目录尚未准备时，只维护已有记录，不接纳新文件。

一致备份采用 [SQLite Backup API](https://www.sqlite.org/backup.html)。[数据库事务](https://www.sqlite.org/lang_transaction.html)保护数据提交，不能直接回滚文件夹创建或文件移动。

只有旧 JSON 的情况复用现有导入校验，再迁入 v2；成功后仍保留原 JSON。损坏、未知版本或状态不一致时停止并报告，不自动回退过期 JSON 或重建空基线。已经使用 v2 后，旧数据库备份也只是升级前快照，不能直接当作最新状态回滚。

## 存储接口与账号隔离

建议增加统一仓库对象和 `AccountStateStore(accountID)` 适配器。仓库管理配置、迁移和连接；worker 只取得自己的基线、记录与必要目录信息。

worker 的保存不修改其他账号，不重写根目录授权，也不修改账号的备注或用户暂停意图。缓存按账号分开，配置操作与扫描状态更新使用不同接口。避免把 M1 的全量删除逻辑简单放进多账号循环。

配置和扫描继续保持单一写入通道。全局数据库写入失败时停止整轮并保留恢复信息；不能因为“账号隔离”就忽略共享数据库故障。单账号授权或文件异常可以隔离，数据库损坏和共享根目录不可用会影响所有依赖账号。

## 添加账号与目录创建

添加流程收集备注和源目录授权，验证源目录身份、重复绑定、同文件系统、目录包含关系和目标名称。取消授权或校验失败时，不改变已有账号。

初始目标建议为 `微信文件/<首次备注>`。名称需处理路径分隔符、空名、保留名称和文件系统冲突；现有未知账号目录不自动复用，以安全的新名称避让，并展示实际保存位置。备注以后变更不影响此路径。

先持久化配置操作计划，再创建属于该操作的临时目录，记录其身份，通过排他改名确定最终目录。基线、源书签和账号配置在事务中一起提交，完成后才让账号参与新增同步。临时目录与操作计划可以中断恢复，不能让半完成账号被 worker 加载。

失败清理仅作用于本次创建、身份仍匹配且为空的目录。若用户已放入文件，保留目录并记录待检查状态。不得删除原有文件夹，也不通过“目录名称看起来正确”认定为本工具所有。

新增账号在添加时建立独立历史基线；恢复移除账号按 C04 复用旧基线，不自动把未知目录当作原账号。账号源目录被重建后即使路径相同，也需明确重新绑定，不能静默继承旧身份。

## 调度与暂停

一个后台进程持有一个写入锁，统一管理多个 worker。M2 首版串行调度，按账号轮次处理，避免引入多进程和同时操作文件的复杂性。

每轮先取得根目录的有效授权，再逐账号检查源授权和身份，维护已有链接与 planned 操作；仅对新增开关开启、归档目录有效的账号接纳新候选。某账号授权、扫描或链接处理失败时记录其错误并继续其他账号。

根目录索引按需创建，在一轮中供所有账号共享；缓存成功和失败结果，使用前复核文件身份。程序自身的移动更新或使相关缓存条目失效；不能把上一轮索引长期沿用。无外部变化的批量维护场景，每个根目录一轮最多完整枚举一次。

账号归档目录不可用时，停止向该目录写入，已有链接能在共享管理范围内维护时继续维护。微信源授权无效时则无法维护该账号链接，但不影响其他账号。M2 先报告目标目录故障，图形重新绑定和搬移设置在 M5 细化。

用户暂停开关与运行故障状态分别展示。重启应用保留用户的暂停意图，授权恢复也不能擅自打开用户关闭的新增开关。恢复暂停后按 C06 补同步，重新开始稳定观察。

## 命令与操作入口

M2 命令已接入，完整参数与停止、恢复后台的操作见 [用户指南](user-guide.md)。

| 入口 | 用途 | 后台运行时 |
| --- | --- | --- |
| `--list-accounts` | 列出稳定 ID、备注、新增开关、移除状态和实际归档位置；即时授权状态用 `--check`，列表不代表后台实时状态。 | 允许只读查询，不迁移。 |
| `--add-account` | 选择源目录、填写备注、建立基线和独立目录。 | 拒绝写入，提示先停止。 |
| `--pause-account <ID>` | 关闭新增接纳，已有维护继续。 | 拒绝写入，停止后设置再启动。 |
| `--resume-account <ID>` | 恢复新增接纳，按 C06 处理积压。 | 同上。 |
| `--rename-account <ID>` | 修改备注，不改目录。 | 同上。 |
| `--remove-account <ID>` | 按 C04 保留数据、清除当前源书签并停止管理。 | 同上。 |
| `--restore-account <ID>` | 按 C04 恢复已移除账号并重新授权。 | 同上。 |
| `--reauthorize-account <ID>` | 更新指定账号的授权，不擅自换源目录或重建基线。 | 同上。 |

`--configure` 保留为初次设置或引导入口，不能再覆盖唯一账号行。根目录授权只保存一份；重新授权不等于切换根目录。未知命令和不完整参数应报错并退出，不能误进入默认后台循环。

当前 LaunchAgent 设置 KeepAlive，停止后台需要正确注销运行中的服务，再于修改后恢复注册。M2 补操作说明，不用删除应用或删除配置来完成普通账号管理。本轮不运行这些真实服务操作。

## 临时样本测试计划

保留 M1 的 38 项回归和 v1 夹具；另用 SQLite v2 的多账号夹具验证新存储适配器、协调器和迁移，不删除原来的行为断言。M2 新增下列验收场景，实际测试数量按落地结果记录，不把计划写成已通过。

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| A01 | 两账号相同源相对路径、相同文件名 | 分别进入账号目录，链接和记录互不覆盖。 |
| A02 | A 保存或清除记录 | B 的基线、计划、链接状态和配置完全保留。 |
| A03 | 重复源目录、目录别名或目录重建 | 重复活跃绑定被拒绝，身份变化不静默继承。 |
| A04 | 备注重复、大小写及目录冲突 | 安全避让，不覆盖、接管或删除已有目录。 |
| A05 | 新增账号已有文件 | 独立建立基线，不整理启用前文件，不改变其他账号的基线。 |
| A06 | 暂停账号的新候选与在途计划 | 新候选不动，已有链接维护和在途恢复继续；其他账号正常。 |
| A07 | 恢复与重启 | 暂停标志持久化，积压行为符合 C06，恢复后重新稳定观察。 |
| A08 | A 源授权失效或源目录不可用 | A 报错，B 继续；不自动新建基线或换绑目录。 |
| A09 | 账号归档目录不可用或被替换 | 不写入未知目录，已有链接的可行维护继续，不影响其他账号。 |
| A10 | A 文件移到 B 的目录或公共项目目录 | A 的关联继续，归属不变；B 后续同名接收安全避让。 |
| A11 | 多账号批量删除和改名 | 共享根目录索引，不按账号重复全量遍历；实际身份再次核对。 |
| A12 | 添加取消、书签写入失败、事务失败 | 账号不会半注册，其他配置完整，本次目录按所有权规则保留或清理。 |
| A13 | 创建目录和注册账号各阶段中断 | 重启只恢复有操作记录的对象，不采用未知目录，不删除用户文件。 |
| A14 | v1 到 v2 正常迁移与反复打开 | 记录数与身份一致，旧目标路径不变，不重复导入旧快照。 |
| A15 | 备份、迁移、版本提交中断或失败 | v1 保持可读，未知版本不重建；备份权限和书签保密性保持。 |
| A16 | 移除及显式恢复 | 遵守 C04，其他账号与实体不受影响，未重新授权前不访问源目录。 |
| A17 | 写入锁被模拟后台持有 | 修改命令失败且不改变数据；只读列表仍可用。 |
| A18 | 共享数据库或管理根目录失败 | 按全局故障停止相应操作，不能吞掉保存错误继续移动文件。 |

所有文件和数据库在新建的随机临时目录中生成，账号 A、B 都是临时源目录；授权失败由接口替身注入，书签测试使用假数据。测试不扫描真实 `xwechat_files`，不打开真实应用支持目录，不创建真实登录项，不运行真实目录的配置或诊断。安装入口继续使用假应用和命令替身。

SQLite v1 样本也由测试生成，包括书签、planned、linked、conflict 记录和历史基线。生产源码保留真实账号目录格式校验，测试通过可注入接口验证核心，不新增供普通用户绕过授权的测试开关。

## M2 实现说明

以下为 M2 的实现记录；M3 已在独立分支扩展为 v3，见 [去重与只读方案](content-dedup-readonly-plan.md)。

核心已落在 `AccountRepository`、`AccountStateStore`、`AccountManager`、`SyncCoordinator` 和 `ManagedRootIndex`；应用入口使用 SQLite v2。M1 的 `SQLiteStateStore` 保留用于 v1 校验、迁移和旧回归夹具。配置操作失败后保留计划与本次目录，按身份继续恢复；未记录身份的孤立临时目录不自动接管或删除，以保留用户文件。

书签只能由实际桌面授权产生，自动测试使用假数据；真实授权窗口取消、签名升级后的书签有效性及登录服务切换尚未实测，留待 M6。自动测试覆盖的是写入失败与事务回滚，并不把它等同于所有桌面授权路径已验证。

提交前复核补齐未完成账号的移除与显式恢复、重名改址计划的保留、已完成操作的幂等恢复，以及链接已安装但状态未提交时的跨目录移动恢复。具体复现与验证见 [验收记录](validation-report.md)。
