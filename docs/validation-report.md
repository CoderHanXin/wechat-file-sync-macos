### 提交前专项复核

本轮重点审查去重清理、中断恢复、数据迁移及只读权限。先在修复前复现异常，再修改状态机并补回归，新增 `ContentReviewTests` 的 11 项测试，使总数从 123 项增加到 134 项；参数化另外覆盖回滚自身的两个中断点和两种反向权限请求。

| 复核发现 | 修复及验证 |
| --- | --- |
| 去重来源已改指新位置，来源事务提交失败后再失去实体时，回滚仍只接受旧目标。 | 链接改址前先持久化允许的目标历史；按当前日志恢复和回滚，冗余内容可还原到源位置。 |
| 临时链接已准备、尚未交换时，实体改名会把本工具的旧临时链接视为未知占用。 | 只识别日志内的旧目标，安全更新准备链接后继续，未知对象仍不删除。 |
| 冗余内容已清理、完成提交前中断，之后实体移动会把有效来源标成冲突。 | 通过日志核对已安装目标，保留正确的来源位置，再由实体维护更新链接。 |
| 实体已标失联，链接首次清理因权限失败后不再重试。 | 对仍有活动来源的失联实体继续核对；权限恢复后清理链接并保留来源历史，已结束来源不自动重建。 |
| 中途父目录被移出源范围并用符号链接重定向，清理仍可能操作范围外临时内容。 | 描述符核对增加根身份和边界检查；交换、回滚及最终移除前重新检查，范围变化时保留工作文件。 |
| 权限操作只检查文件身份，可能经父目录链接修改管理根目录外的原文件。 | 权限入口匹配实体位置并检查管理范围，chmod 前后复核；修改后目录变化保留未完成任务，不虚报提交成功。 |
| 未完成权限任务与新的显式请求相反时，仅完成旧任务便返回。 | 先安全完成旧任务，再应用新请求；CLI 不因旧任务尚未写回权限记录而跳过请求，原写位保持可恢复。 |
| 迁移时 linked 与 conflict 共享目标，合并实体状态会自动消除冲突来源。 | 只共享证据一致的 linked 迁移实体；planned/conflict 保留独立恢复/冲突证据，冲突来源不在普通扫描中被自动接管。 |
| 首个历史副本的元数据不兼容时立即停止，忽略后续兼容副本。 | 继续查找可安全合并的候选；没有兼容副本时仍保留源内容并报告。 |

全部复现和权限、目录重定向操作都位于随机临时夹具内；测试中的“范围外目录”也在同一夹具，不是真实用户目录。复核还验证回滚交换后及回滚临时链接清理后再次中断可幂等完成，权限已变更但目录随后移出的任务可在目录恢复后继续，原权限不丢失。

### 构建与隔离

`bash build.sh` 成功，ARM64 / x86_64 通用应用通过 `codesign --verify --strict`，两种架构 `--self-test` 均通过，x86_64 经 Rosetta。自测新增 v3 临时样本，验证同内容跨扩展名去重、实际只读、共享实体改名和失联记录，同时保留既有模拟流程。

帮助入口显示 M3 命令；未知命令、混用 `--self-test --configure`、无效只读参数及错误诊断参数均以错误码退出，未进入真实配置或后台。`bash test-install.sh` 使用假应用和命令替身通过正常安装卸载、配置取消、服务注册失败及已有安装保护；没有注册真实登录项。

所有文件、数据库、假书签、源目录和元数据都在随机临时目录生成。新增二进制样本使用 `wechat-content-smoke-<UUID>`；自动回归仍使用隔离夹具。ACL 测试对临时文件调用 `/bin/chmod`，扩展属性、资源叉和硬链接样本也只在临时夹具内创建。

本轮没有读取或修改真实微信文件，没有打开、迁移本机真实应用配置，不执行真实账号配置、诊断或后台，不安装或操作真实 LaunchAgent。旧数据库备份样本均由测试生成。

### 限制和未覆盖

- 真实微信的下载、转发、不同扩展名预览与默认应用、编辑器只读提示、暂停续传均未验证；签名沙盒真实授权、升级和登录生命周期仍待 M6。
- macOS 13 与 Intel 实机、真实磁盘写满、异常掉电和文件系统损坏未验证。数据库错误使用触发器/检查点注入，不等同于所有物理故障。
- 观察摘要每账号默认每轮 4 MiB、最多一个跨轮任务；目标内容复核及操作清理前核对仍按单文件完成，大文件会延长当前轮次，不承诺严格时间片抢占。
- 元数据校验限制总量 64 KiB；不兼容属性、复杂 ACL、不可变标记和其他硬链接采取保留并报告。没有宣称穷尽所有 macOS 元数据组合或所有应用的写入方式。
- 临时交换内容不是长期备份；共享实体在清理完成后被用户删除时不保留隐藏原件。M3 仅保留最小失联记录，M4 手动恢复和保留期限尚未实现。
- CLT 的测试框架最低系统与路径警告、x86_64 兼容包切片链接警告仍存在，实际本机构建和 Rosetta 自测通过；不据此扩大支持范围声明。

### 提交前重点复核与修复

本轮重点复核多账号限定的读写范围、v1 备份与迁移事务，以及配置和文件操作的恢复。先新增回归在修复前复现了以下四处问题，再修复并运行全量测试：

| 问题 | 修复与结果 |
| --- | --- |
| 迁移账号归档避让同名目录，最终注册失败；随后移除会把待恢复路径覆盖回旧路径。 | 移除只更新计划中的移除状态与源授权，保留操作自己的目标、临时名和目录身份；重新授权恢复后使用避让路径，用户原目录内容保持不变。 |
| 新账号尚未最终注册时，无法按列表中的 ID 移除其未完成操作。 | 在同一事务中保留原 UUID 与基线、标记移除并清空授权，停止自动恢复；显式恢复后复用原基线。注入计划更新失败时，账号、基线和授权一起回滚。 |

### 复查与测试隔离

提交前复查增加了三项回归。先在修复前复现“移动后目标替换导致未知文件被回退到源路径”和“中断后目标改名导致链接无法恢复”，再修改移动后检查和 planned 阶段的身份查找，并验证旧名被其他内容占用时两份文件均保留。另去掉了错误注入闭包对整个测试夹具的强引用，保证临时目录可随夹具释放清理。

核心测试在系统临时目录创建 `wechat-core-tests-<UUID>`，里面的 `wechat-file`、`自定义资料目录`、数据库、文档内容及符号链接均由测试生成。路径越界测试使用的“外部文件”也在同一个临时夹具内。旧格式测试使用自行生成的 JSON 和假书签数据，不读取本机真实配置或钥匙串。

二进制的 `--self-test` 使用 `wechat-sync-<UUID>` 临时目录。账号目录识别仅构造预期路径验证命名格式，没有枚举或读取真实 `xwechat_files`。该入口不执行真实配置或后台同步。

安装模拟在临时目录准备假应用，将测试进程的 `HOME` 指向临时目录，并用替身覆盖 `launchctl`、`codesign` 和 `ditto`；不会向真实登录项或应用目录安装程序。本轮没有执行真实 `--configure`、`--diagnose` 或后台同步，不使用真实微信文件样本。

### 构建与安装检查

执行 `bash build.sh` 生成通用架构应用、本机临时签名的 ZIP 包与 SHA-256 校验文件。ARM64 和 x86_64 二进制均使用系统 SQLite，不在应用中打包测试框架。

安装卸载模拟测试 `bash test-install.sh` 通过，覆盖正常安装与卸载、配置取消、后台服务注册失败回滚以及已有安装保护。此模拟不验证真实 LaunchAgent 启动及桌面授权。

ARM64 和 x86_64 的 `--self-test` 均通过，通用应用经 `codesign --verify --strict` 验证通过，`lipo` 确认同时包含两种架构。Intel 路线使用 Rosetta，不代替 Intel 实机；构建器仍报告 x86_64 缺少兼容包切片的警告。
