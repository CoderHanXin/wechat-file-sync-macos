## 环境

- Apple 芯片，macOS 27.0，构建号 26A425。
- Apple Swift 6.4，当前使用独立 Command Line Tools，无需完整 Xcode 运行本轮构建与测试。
- 系统 SQLite 3.54.0。
- 应用构建目标仍为 macOS 13，ARM64 和 x86_64；核心测试使用 Swift Testing。

批量删除用例包含 30 条活动同步记录和 100 个其他归档文件，单轮管理目录完整遍历 1 次，状态保存调用 1 次；原实现的讨论阶段验证为各 30 次。此结果用于验证消除重复工作，不代表大规模文件的完整性能基准。

测试构建仍有当前 CLT 的路径警告；其 Testing 框架的构建系统最低版本为 macOS 14，测试运行于 macOS 27.0。应用自身仍通过单独构建脚本以 macOS 13 为目标，两者不能混同为 macOS 13 实机测试结论。

## 复查与测试隔离

提交前复查增加了三项回归。先在修复前复现“移动后目标替换导致未知文件被回退到源路径”和“中断后目标改名导致链接无法恢复”，再修改移动后检查和 planned 阶段的身份查找，并验证旧名被其他内容占用时两份文件均保留。另去掉了错误注入闭包对整个测试夹具的强引用，保证临时目录可随夹具释放清理。

核心测试在系统临时目录创建 `wechat-core-tests-<UUID>`，里面的 `wechat-file`、`自定义资料目录`、数据库、文档内容及符号链接均由测试生成。路径越界测试使用的“外部文件”也在同一个临时夹具内。旧格式测试使用自行生成的 JSON 和假书签数据，不读取本机真实配置或钥匙串。

二进制的 `--self-test` 使用 `wechat-sync-<UUID>` 临时目录。账号目录识别仅构造预期路径验证命名格式，没有枚举或读取真实 `xwechat_files`。该入口不执行真实配置或后台同步。

安装模拟在临时目录准备假应用，将测试进程的 `HOME` 指向临时目录，并用替身覆盖 `launchctl`、`codesign` 和 `ditto`；不会向真实登录项或应用目录安装程序。本轮没有执行真实 `--configure`、`--diagnose` 或后台同步，不使用真实微信文件样本。

## 构建与安装检查

执行 `bash build.sh` 生成通用架构应用、本机临时签名的 ZIP 包与 SHA-256 校验文件。ARM64 和 x86_64 二进制均使用系统 SQLite，不在应用中打包测试框架。

安装卸载模拟测试 `bash test-install.sh` 通过，覆盖正常安装与卸载、配置取消、后台服务注册失败回滚以及已有安装保护。此模拟不验证真实 LaunchAgent 启动及桌面授权。

ARM64 和 x86_64 的 `--self-test` 均通过，通用应用经 `codesign --verify --strict` 验证通过，`lipo` 确认同时包含两种架构。Intel 路线使用 Rosetta，不代替 Intel 实机；构建器仍报告 x86_64 缺少兼容包切片的警告。
