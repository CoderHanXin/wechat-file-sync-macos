M0 核心决策已记录，M1 至 M3 已实现并提交；M3 已完成专项复核和本地临时样本验证，尚未发布。M4 已实现最小 v4 和两条恢复路径；0.6.1 设置复核后核心回归 174 项通过，尚未发布；M5 已实现最小菜单栏与设置窗口，M6 安装生命周期已实现，真实环境验收待用户另行允许。仓库根目录的 [README](../README.md) 继续说明现有版本的行为。

当前方向是把微信新接收的文件整理到本地，按账号归档相同内容，并维护微信原路径到实际文件的关联。用户已经确认内容去重、多源关联、删除后的关联恢复、微信侧清理不反向删除归档文件，以及可配置的只读保护；不提供创建可编辑副本、文件编辑或版本管理功能。

## 状态约定

- **已确认**：用户明确同意或提出的行为要求。
- **规划范围**：本次讨论希望纳入产品规划，但细节尚未全部确定。
- **建议**：为了让方案可执行而提出的默认选择，可在实现前调整。
- **待决定**：会影响文件保存、删除、权限或迁移的具体选择，应在相应阶段开始前确定。
- **暂不纳入**：本轮计划排除的功能，不应在实现中顺带增加。

需求状态以 [需求与行为规则](requirements.md) 为准。架构和计划中的建议不自动升级为用户已经确认的决定。

## 仓库与开发方式

M1–M6 与账号发现设置已经整合到 `main`（功能基线 `5376b87`）。以 `main` 作为后续开发起点，已完成的功能分支在确认整合并推送后清理；历史提交和阶段文档保留。主分支整合不等于正式发布，真实环境验收状态不变。

当前在此 fork 上继续开发，M4 基于已提交的 M3 规划，保留原有历史、许可证和作者声明。后续功能在按实际工作命名的独立分支推进。

简化 M4、最小设置界面和安装流程已实现；下一步是用户审阅后明确样本范围的真实环境验收。以简洁为产品约束，不把诊断入口逐一扩展为界面功能。每个阶段以行为测试和实际验收结果完成，不以界面出现或代码编译成功作为唯一完成条件。
