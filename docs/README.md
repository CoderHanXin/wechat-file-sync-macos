# 微信文件同步开发规划

整理日期：2026-11-18。上游起点：`e2061d4`；M3 开发基线：M2 提交 `4951d59`。

M0 核心决策已记录，M1 核心重构与自动回归已实现；M2 多账号核心和命令管理也已在当前分支实现；M3 已在当前工作区实现内容去重与只读核心；手动恢复和完整配置界面仍属后续阶段。仓库根目录的 [README](../README.md) 继续说明现有版本的行为。

M2 的实现边界见 [多账号实施方案](multi-account-plan.md)。M2 已在 `codex/multi-account-sync` 完成提交与推送，基线为 `4951d59`；尚未发布，真实微信与桌面授权留待 M6。

M3 在 `codex/content-dedup-readonly` 整理 [内容去重与只读实施方案](content-dedup-readonly-plan.md)。本轮三项选择已确认，已实现 v3 迁移、去重、只读及临时样本回归，已完成提交前专项复核，尚未发布。

当前方向是把微信新接收的文件整理到本地，按账号归档相同内容，并维护微信原路径到实际文件的关联。用户已经确认内容去重、多源关联、删除后的关联恢复、微信侧清理不反向删除归档文件，以及可配置的只读保护；不提供创建可编辑副本、文件编辑或版本管理功能。

## 状态约定

- **已确认**：用户明确同意或提出的行为要求。
- **规划范围**：本次讨论希望纳入产品规划，但细节尚未全部确定。
- **建议**：为了让方案可执行而提出的默认选择，可在实现前调整。
- **待决定**：会影响文件保存、删除、权限或迁移的具体选择，应在相应阶段开始前确定。
- **暂不纳入**：本轮计划排除的功能，不应在实现中顺带增加。

需求状态以 [需求与行为规则](requirements.md) 为准。架构和计划中的建议不自动升级为用户已经确认的决定。

## 仓库与开发方式

当前在此 fork 上继续开发，基于已提交的 M2 实现 M3，保留原有历史、许可证和作者声明。后续功能在按实际工作命名的独立分支推进。

后续实现应先稳定同步核心，再加入多账号、内容去重和界面。每个阶段以行为测试和实际验收结果完成，不以界面出现或代码编译成功作为唯一完成条件。
