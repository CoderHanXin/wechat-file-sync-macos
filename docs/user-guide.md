# 使用指南

更新日期：2026-11-20。本文说明开发分支的桌面设置流程。安装与升级见 [部署说明](deployment.md)，历史实现结果见 [验收记录](validation-report.md)。

## 首次设置与日常使用

打开 `WeChatFileSync.app` 后驻留菜单栏。首次使用时自动打开“账号与文件”设置页。

1. 点击“允许访问微信文件夹…”，在系统窗口确认 `xwechat_files`。窗口默认打开当前用户主目录下的 `Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files`。
2. 在设置页的账号列表选择要同步的账号。列表直接显示完整目录名。
3. 选择文件保存位置，确认页面上显示的账号和位置后，点击“开始同步”。

取消系统目录窗口会回到打开它的页面或浮层。在同一次运行期间，关闭设置窗口后仍可回来继续首次设置。以后点击“添加账号”，按钮旁会显示可添加列表，点击对应账号旁的“添加”即可。有效的微信文件夹授权和已有保存位置会被复用。“微信账号”标题右侧显示同步状态，选择有问题的账号可查看原因。

“通用”中可查看已设置的共享保存位置、登录启动和应用信息。“更多操作”提供停止或恢复管理及文件关联恢复。

新文件进入 `<保存位置>/微信文件/<添加时账号目录名>/`。初次已有的微信普通文件作为历史基线留在原处；不是导入全部聊天附件。管理根目录可自定义，下载只是默认建议。源目录与根目录须位于同一文件系统，不能相同或互相包含。

在根目录内改名或整理到子目录会继续跟踪。即使文件放进另一个账号的文件夹，归属仍按原账号。已有账号的旧归档目录保持原名，不自动搬动。尚未添加账号且没有未完成配置时，可以重新选择根目录；已有账号记录（包括已移除账号）后只提供原目录重新授权，不搬迁归档。

转发已同步的附件时，微信有时会创建一个指向同一保存文件的新链接。同步开启时，只要程序在新链接仍有效时识别到它，就会一起维护两个微信入口。

关闭设置窗口继续同步。可从菜单栏重新打开设置或在访达中打开根目录。应用处于前台时也可按 `⌘,` 打开设置。退出应用等待当前串行动作完成后停止同步。登录启动默认关闭，用户可在设置中开启；系统要求批准时到登录项设置允许。它不会在本次退出后强制拉起应用。

点击菜单栏图标可查看当前状态。「等待新文件」表示程序检查过微信文件夹，当前没有待处理的新文件。微信仍显示「接收文件」时，先在微信里接收。「正在处理新文件」表示程序已发现文件，正在等待写入完成、校验或保存。遇到需要处理的问题时，点击「查看同步问题」可前往对应账号或保存位置。

## 账号与只读

关闭“同步新文件”只停止新增接纳，已有关联和在途操作继续维护；继续后重新观察、补同步仍在微信目录的新增文件。移除管理保留文件、链接、基线及记录，清除该账号保存的书签并停止访问其源目录；显式重新选择原微信文件夹后可恢复同一账号。其他账号可能仍持有同一父目录访问许可，停止管理不等于系统级撤销某个子目录权限。不可用或身份已变化的目录不自动接管。

“文件只读”初始开启，只影响未来新建的归档文件。新来源复用已有归档时保持其权限；已有可写文件不会因开关改变而批量只读。普通只读用于防误改，不能阻止所有编辑器替换文件，也不保证强制另存。多个来源共享一份实体，直接编辑或删除会影响这些入口。

旧文件批量权限调整保留为低频 CLI：只恢复本工具确实移除的写位，不把用户原有只读强行解锁。特殊 ACL、不可变标记及其他硬链接等不安全情况保留内容并报告。

## 删除与两条恢复路径

删除或移出根目录后，程序在范围内找不到文件，会清理仍属于本工具的失效链接，保留必要元数据。访问或枚举失败只报错，不能当作永久删除。没有隐藏原件库，记录不能找回已丢失的字节。

原文件以相同身份回到根目录，后台约每 30 秒批量查找失联身份，自动恢复此前由程序清理的来源。微信侧自行清理、原因未知、源路径被新生命周期使用或占用时不自动重建；移除账号不访问源，暂停仍维护。

找到另一份副本时，先自行放回根目录。在账号页的“更多操作”中选择“恢复文件关联…”，选择原来的文件记录和找回的文件，查看账号、原位置、候选大小及各来源信息。摘要匹配、不同或无法核对均会明确告知；可取消部分来源，再确认恢复。原名、路径和大小帮助识别，不会显示并不掌握的联系人、群聊或接收时间。

确认表示你希望旧入口指向所选内容；它不能绕过源路径占用、父目录缺失、越界、跨账号或在途操作检查。恢复保留候选名称、位置和权限，不搬动、不删除、不合并候选。目标在预览后变化则重新预览。

再次接收相同内容正常保存新文件，不凭摘要自动恢复旧关联；可手动把它选作恢复副本。必要记录长期保留，历史清理暂缓。恢复仅指本地链接，不保证微信历史消息或服务器附件仍可用。

## 文件夹访问

选择文件夹是通过 macOS 系统窗口允许本应用访问该目录，程序保存安全书签以便下次启动继续使用。它不是修改文件的只读权限，也不是微信登录授权；系统设置中没有可任意添加文件夹的开关。

已添加的账号无法访问时，账号旁会显示「重新允许访问…」。请选择原来的 `xwechat_files`，程序会核对原账号目录。保存位置的修复在「通用」中操作。

## CLI 与诊断

设置窗口与扫描共用串行写入通道，不需要手工停服务。CLI 写入前仍须先退出菜单栏应用，或停止手动运行的 `--background`。不要将无参数应用再注册为 KeepAlive 服务。

下例 `APP` 只用于当前 shell 的命令路径，不影响系统配置：

```sh
APP="$HOME/Applications/WeChatFileSync.app/Contents/MacOS/WeChatFileSync"
"$APP" --help
"$APP" --list-accounts
"$APP" --list-file-issues ACCOUNT_ID
"$APP" --check
```

列表不迁移或主动读取文件内容；`--check` 会检查现有授权和目录。`--diagnose` 会在授权目录创建临时文件，必须先退出应用。当前状态不可读时只报告错误，不回退旧 JSON 或重建空库。

| 命令 | 用途 |
| --- | --- |
| `--configure` / `--add-account [--name 备注]` | 兼容入口，仍选择账号的 msg/file；未传 --name 时使用账号目录名。 |
| `--pause-account ID` / `--resume-account ID` | 暂停／继续新增。 |
| `--rename-account ID --name 备注` | 改备注，不改归档目录。 |
| `--remove-account ID` / `--restore-account ID` | 移除管理／显式恢复并重新授权。 |
| `--reauthorize-account ID` / `--reauthorize-root` | 重新授权原目录，不搬迁。 |
| `--set-read-only ID on\|off` | 未来新建归档的默认值。 |
| `--apply-read-only ID on\|off` | 显式核对并调整已登记实体，不强行恢复未知权限。 |
| `--recover-accounts` / `--recover-operations [ID]` | 继续已有配置或文件任务，不按前缀盲删工作文件。 |
| `--restore-links ACCOUNT ENTITY --file /绝对路径` | 预览副本，选来源后输入 RESTORE 才执行，关闭输入取消。 |
| `--background` | 手动运行命令行同步，诊断用途；不能与菜单栏同时运行。 |
| `--self-test` | 仅临时样本自检，在打开真实配置之前处理。 |

CLI 的副本恢复与设置调用同一服务，预览不写入长期任务；只有确认执行的在途操作才自动继续。安装辅助 `--check-stopped` 和 `--disable-login-item` 由脚本调用，正常配置不需使用。

## 状态与限制

独立应用标识为 `0xRock3.WechatFileSync`。沙盒容器中的 Application Support/WeChatFileSync/state.sqlite 保存 v4 状态和授权，CLI 与菜单栏共用状态及写锁。旧测试版的标识切换见 [部署说明](deployment.md#更换应用标识)。

界面区分暂停、移除、等待配置与扫描／授权错误。进程存在不等于所有文件正常；无法完成的内容留在现场，通过状态和 `--list-file-issues` 查看来源、操作及临时位置。

微信稳定观察窗口不能证明下载一定结束；不同扩展名的真实预览和打开兼容性仍需验收。本工具不编辑文件、不管理版本、不读写聊天数据库、不下载历史附件、不跨账号合并或跨盘搬运。

## 不接触真实微信的人工界面检查

在图形会话的终端中运行：

```sh
bash test-desktop.sh --manual
```

这是单独编译的测试窗口，不是安装后的正式应用。标题含“临时样本预览”，账号为假账号，目录和数据库都在随机临时目录中；不启动真实同步，不读取真实配置，不打开微信目录或操作登录项。目录授权、账号管理、只读设置和登录启动等按钮均禁用并移除动作，避免误触。

本阶段检查：

1. 窗口文字、中文、路径、账号备注和控件位置是否清楚，是否截断、重叠或显示异常。
2. 是否能分清账号状态、“新建归档只读”和文件关联恢复的说明。
3. 关闭窗口后菜单栏预览图标是否仍在，从其“设置”能否重新打开窗口。
4. 从预览菜单选择“退出”或按 Command-Q，终端命令应结束，临时样本自动清理。

记录问题时说明所在控件、操作步骤、预期和实际结果。当前是只读的外观／窗口生命周期检查，禁用按钮的业务、真实授权、同步和登录启动仍留待后续受控验收。此阶段无需运行 Install.command、打开正式候选应用或添加真实账号。

不带 `--manual` 的 `bash test-desktop.sh` 仍是自动窗口／队列检查，窗口会自动关闭，不适合人工慢慢查看。

### 设置文案约定

界面将可配置管理根目录统一称为“文件保存位置”：它既是文件的保存范围，也是改名、移动后继续寻找文件的范围；每个账号在其中有自己的子文件夹。账号原微信目录的长路径放在鼠标提示中，不占用主界面。

“暂停新文件同步”只暂停新增，已保存文件的改名、移动仍维护；“修改账号备注…”只改本工具中的显示名称。“重新允许访问微信文件夹…”用于重新允许读取原账号文件夹；已停止管理的账号则显示“恢复管理此账号…”。“停止管理账号…”保留文件，不删除微信账号。

删除共享文件、自动恢复和不备份的细节放在操作提示与恢复流程中；主界面只保留短说明。临时预览模式仍禁用业务按钮，避免触及真实目录和登录项。
