# 构建、安装与部署

当前本地测试包为 `0.6.9-test`。历次构建、隔离测试和真机验证见 [验收记录](validation-report.md)。

## 构建

依赖 macOS Command Line Tools 的 Swift、系统 SQLite、AppKit、CryptoKit 和 ServiceManagement，无第三方运行依赖。当前命令行路线不要求完整 Xcode。

```sh
bash test.sh
bash build.sh 0.6.9-test
bash test-install.sh
```

输出 `dist/WeChatFileSync-v0.6.9-test-macOS.zip` 和同名 `.sha256` 文件，包含通用 `WeChatFileSync.app`、安装与卸载脚本、许可证和文档。目标 macOS 13+，ARM64／x86_64。当前为 ad-hoc 本地签名，Intel 实机验证、公证和下载后首次启动兼容性分别验收。

`bash test-desktop.sh` 另编译 `DESKTOP_TESTING` 图形夹具，仅临时假账号，不启动真实 worker。需要可连接 WindowServer 的图形会话；没有既有屏幕录制权限时不请求权限，保存文字 PDF 并检查结构，完整原生控件外观另行人工验证。生产包不包含测试入口。人工查看布局可用 `bash test-desktop.sh --manual`；它只保留假账号窗口，禁用业务和登录项动作，详见用户指南。

## 安装与升级

解压完整目录后运行 `Install.command`，目标为 `~/Applications/WeChatFileSync.app`。源包及已有目标的标识必须为 `0xRock3.WechatFileSync`，脚本校验签名和可执行文件，不覆盖符号链接或其他应用身份。

安装只复制和打开应用，不运行账号配置、不注册登录项、不访问微信。打开后在设置中选择根目录与账号。用户已确认没有原版安装，因此不增加旧版容器自动导入功能。

升级前从菜单栏退出；关闭窗口仍在运行。脚本用已有应用的辅助命令检查 GUI 实例和状态写锁，未退出则拒绝升级，不强制杀进程。复制到同一 Applications 目录下的独占 staging，验证后将旧应用暂存，再改名安装并验证；复制、签名或替换失败时按实际目录身份恢复旧应用；改名后收到终止信号也能核对回滚。回滚本身失败则保留旧应用备份并报告位置，不删除唯一副本。成功后移除 staging 和旧应用临时副本，不改数据库或归档。

安装完成但系统未能打开时保留有效安装，提示在访达手动打开，不因打开失败删除应用。安装过程中请勿重新启动旧应用或同时运行另一份安装／卸载。发现已运行的原作者／早期脚本服务时拒绝继续，要求先自行停用，不同时运行新旧处理者。

### 更换应用标识

如果已安装使用 `io.github.coderhanxin.wechat-file-sync` 的测试版（例如 0.6.8-test），先退出旧版并运行旧版安装包里的 `Uninstall.command`，再运行 0.6.9-test 的安装脚本。旧版卸载脚本会处理旧登录项。

新版在自己的沙盒容器中创建配置。重新选择微信账号和保存位置后，只跟踪新建立的文件关联。此前归档和微信链接留在原位置；如果保存位置里已有同名归档文件夹，新账号会另选可用文件夹。

## 登录启动与退出

默认不开启登录启动，在设置中由用户显式启用。采用系统 [`SMAppService.mainApp`](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp)，状态需批准时提示到系统设置允许。只注册主应用，不创建 KeepAlive LaunchAgent 或额外守护进程。

0.6.4-test 已由用户验证可通过设置开关加入或移除系统登录项。重启并登录后的实际启动仍待验证，详见 [验收记录](validation-report.md#064-test-登录项真机验收)。

关闭窗口继续运行，退出等待当前串行动作结束后释放状态写锁，不在本次会话重新拉起；退出不取消下次登录启动。用户强制结束时由既有文件操作日志在下次启动核对，不能将其等同于真实掉电耐久验证。

## 卸载与数据保留

先从菜单栏退出，再运行 `Uninstall.command`。脚本校验身份和签名，检查已停止，调用该应用注销登录启动；注销失败则不删除应用，避免留下无法处理的启动项。注销后再次检查父目录与应用身份，位置变化时拒绝删除；否则只移除 `~/Applications/WeChatFileSync.app`。

归档文件、微信链接、配置数据库及迁移快照保留。链接仍指向实体，所以卸载后文件仍可通过有效链接打开，但后续改名、移动和删除不再跟踪。不自动删除容器、归档、聊天目录或旧快照；删除这些数据不纳入卸载。

## 真机验收

此前的测试版已完成保留配置升级、登录项注册和移除。0.6.8-test 上，用户验证了转发后再次改名，两条聊天消息均可打开，保存目录中只有一份文件。尚待验证的场景包括：

- `0xRock3.WechatFileSync` 首次安装、授权、添加账号和重新打开后的授权复用。
- 开启「登录时启动」后，重启并登录时实际启动。
- 不同扩展名的微信预览、只读编辑提示、删除与恢复，以及对已声明系统和架构的实机验证。

自动回归使用临时样本。遇到微信为相同内容生成两份独立文件的真实样本时，再补充真机去重验证。
