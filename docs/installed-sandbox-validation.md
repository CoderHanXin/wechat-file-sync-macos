# 安装后的独立沙盒样本验收

日期：2026-11-19～20。本文“正式应用”指默认应用标识下已安装的开发测试版本，不代表已正式发布。分支：`codex/installed-sync-fixes`；起点 `main` / `14c4931`。修复候选：`0.6.2-test`，未发布。

## 范围与用户配置保护

用户授权安装候选，并以两个假账号、独立保存目录验收，不操作真实微信文件。首先核对 0.6.1 ZIP 的 SHA-256、应用标识与严格签名，执行安装脚本安装到用户 Applications；初始无旧安装或配置。

期间用户自行在弹出窗口配置了真实账号。自动验收发现后立即暂停进程；只读检查本应用状态库没有已同步实体、来源、在途操作或迁移任务。用户确认“保留配置并退出，继续隔离假账号验收”，随后退出正式应用，未撤销或重建其账号配置，未移动、删除或编辑真实微信文件。用户手动配置建立的历史基线原样保留。

后续使用 `WeChatFileSyncAcceptance.app`，应用标识为仅本轮使用的独立验收标识，与正式应用容器分离；两者使用相同可执行内容和 App Sandbox、用户选择目录读写、安全书签权限。重新签名改变签名数据，因此通过对临时副本剥离签名后比较可执行内容，核对一致。系统文件夹窗口只确认本轮创建的假 `xwechat_files` 和独立保存位置，没有注入或模拟书签。隔离副本更改标识后重新 ad-hoc 签名，不能等同于原始包在正式标识下的所有升级、登录及真实微信兼容验收。

界面工具不可用时，经用户明确允许改用 AppleScript；辅助访问权限由用户亲自在系统设置开启，没有改系统权限数据库。只操作本软件及其文件夹选择窗口。样本曾位于项目 `build/installed-acceptance-<id>/`；关键证据与检查结果保留于该目录的日志、`manifest.json`、`results.json`、`final-test-state.json`。

## 发现并修复

### 沙盒隔离属性阻断去重

本机沙盒将 `com.apple.quarantine` 附加到归档及程序创建的准备链接；实测 RENAME_SWAP 还会把准备链接的隔离标记传播到待清理普通文件。旧代码逐字节比较全部扩展属性，先在接纳阶段拒绝，首次兼容调整又在交换后的清理阶段回退。文件正文均保留，没有误删。

最终规则：

- 归档已有隔离属性而新来源没有时，可以复用归档，但归档属性原样保留。
- 仅当来源原先没有隔离属性时，交换前读取自有准备链接上系统生成的精确标记并持久化到操作记录。
- 清理时只兼容与这份记录逐字节相同的传播标记；仍检查内容、身份、权限、其他属性及目录范围。归档上的隔离属性逐字节未改变。
- 来源原有不同隔离属性、传播标记变化或旧记录缺少标记时，继续保留原件或安全回退，不盲目清理。
- 不解析私有隔离位，不删除文件隔离属性，不关闭沙盒，不增加 executable 或其他文件访问权限。

`ContentOperation.swappedQuarantine` 是可选操作载荷；SQLite 继续为 v4，不批量迁移历史数据。旧操作缺少记录时保守处理。回归覆盖正常交换、中断重启、标记被修改和旧记录缺失标记。较早失败样本已原样移入本轮诊断目录；不为重试自动解除其隔离属性。

Apple 的 [App Sandbox 权限说明](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html) 与 [Launch Services 隔离机制说明](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/LaunchServicesKeys.html) 说明系统隔离保护；RENAME_SWAP 的具体传播结果来自本机独立沙盒探针实测，不假定其他系统版本行为完全相同。无法核对时保持保守回退。

### 账号切换被状态刷新干扰

原实现每次状态刷新都重建账号菜单并恢复旧选择，可能干扰用户切换。现在只在账号列表／标题变化时重建，普通刷新沿用当前选择；新增账号完成后显式选择新项。补充双账号窗口回归，并在安装副本验证选择、路径与开关作用对象一致。

### 首次尺寸与未解决问题显示

首次展示明确设置 960×720，内容最小尺寸 880×680；安装副本实测默认尺寸正确，调整为 900×700 后关闭重开保持尺寸。已有界面布局不新增设置。

仍留在源目录等待重试的失败文件，等待下一次稳定观察期间继续显示问题，避免在“需要处理”和“正常”之间跳变；问题文件离开当前源路径后不把历史记录永远显示成当前错误。
