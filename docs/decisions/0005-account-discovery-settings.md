# 账号发现与简化设置

日期：2026-11-19。用户确认本轮先更新文档再实施；测试只使用临时样本，不扫描真实微信目录。

## C15 选择父目录，再选择账号

用户在系统文件夹选择窗口中选择 `xwechat_files`，程序列出其中可用的账号目录。默认定位到当前用户主目录下的 `Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files`，不写死用户名。排除 `all_users` 和 `Backup`（不区分大小写），且只接受具有真实 `msg/file` 子目录的直接子目录；不跟随账号、msg 或 file 的符号链接。单个不可访问子目录不影响其他账号；父目录读取失败仍报错。发现仅检查目录结构，不读取文件内容或接纳新文件。新发现的账号必须由用户选择并确认，不能自动开启。

直接显示完整账号目录名，不猜测后缀含义、不读取微信昵称、不填写备注。移除桌面备注编辑入口；历史显示名称、归档路径与 CLI 兼容接口保留，不自动改名或搬动文件。

## C16 账号在前，保存位置在后

首次添加：选择微信文件夹 → 选择账号 → 选择文件保存位置 → 确认添加。已有保存位置时直接复用，账号新文件仍存入该位置下各自的独立子目录。文件跟踪范围是整个保存位置，账号归属不因范围内移动而改变。

设置只有“账号与文件”和“通用”两页。前者放账号选择、添加、同步新文件开关、只读开关、账号文件夹与打开入口；停止／恢复管理、修复访问和文件关联恢复收起为低频操作。通用放共享保存位置、登录启动与应用信息。没有搜索、外观、语言或功能占位页。

关闭“同步新文件”只暂停接纳，继续维护已有链接和完成在途操作（C02）；与访问失效分开处理。只读开关只影响之后新建的实体，复用已有实体保留权限（C09）。

## C17 文件夹访问与账号管理分开

系统文件夹选择窗口授予沙盒访问范围，安全书签用于重启后再次访问；它不是修改文件权限、微信登录授权，也不是在系统设置中为任意目录添加开关。无需预先要求完全磁盘访问权限。实际访问失败才提示重新选择原文件夹，不凭“已保存书签”显示“已授权”。

新添加账号在既有 source_bookmark 字段保存所选父目录的书签；每次使用时仍校验账号的固定 msg/file 路径、真实目录结构和原目录身份。授权父目录不等于接管全部账号。旧版单账号 msg/file 书签继续可用，下一次添加可重新选择父目录；不自动迁移旧授权。

不新增 SQLite 表或版本：书签仍是不透明授权数据，旧程序的精确路径核对会拒绝父目录书签，不会扩大旧程序访问范围。发现其他账号时可复用某个仍在管理账号的父目录书签；全部账号停止管理后不额外保留独立父目录授权，下次添加重新选择。

此项补充 C04：停止管理清除该账号保存的书签并停止访问其源目录；其他账号仍可能持有同一父目录访问许可，因此不承诺系统级撤销单个子目录权限。恢复已停止账号仍须显式确认并重新核对原目录身份，不能因为发现目录就自动恢复；历史基线与 UUID 不变。

## 实施与验证

开发分支 `codex/account-discovery-settings`。按目录发现与授权校验 → 设置重排与添加流程 → 临时样本回归推进。覆盖无效目录、大小写排除、重定向目录、发现不接纳、账号隔离、停止与恢复、旧书签兼容、开关语义和界面布局。真实微信访问、沙盒书签跨启动和登录启动仍留待明确授权后人工验收。
