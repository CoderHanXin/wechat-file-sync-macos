# 多账号配置与暂停行为

日期：2026-11-18。基线：M1 提交 `9b29fbf`。开发分支：`codex/multi-account-sync`。

以下六项已由用户确认。M2 已在当前分支实现，具体方案见 [多账号实施方案](../multi-account-plan.md)。

## C01 配置修改前停止后台

M2 使用命令行账号管理和已有目录授权窗口，完整设置界面在 M5 实现。添加、修改、暂停、恢复和移除账号前，先停止后台同步；后台运行时，写入型配置命令拒绝执行，保留现有配置。只读账号列表和状态查询可以继续使用。

当前安装服务设置了 KeepAlive，仅终止进程会被重新拉起。使用 LaunchAgent 时，停止与恢复指正确执行 `bootout` 和 `bootstrap`，保留应用和配置。M2 应提供清楚的操作说明，本轮开发不操作本机真实服务。

## C02 暂停只影响新增同步

暂停某个账号后，不再接纳新的候选文件；继续维护已经管理的文件链接，包括改名、管理范围内移动和删除处理。已持久化的在途操作继续恢复，避免遗留已移动但尚未建立链接的文件。

持久化的暂停开关表达用户意图，与授权失效、目录不可用等运行故障分开。共享管理根目录不可用会影响依赖它的账号；一个账号的源授权失效不影响其他账号。

暂停期间尚未接纳的新文件，恢复后按 C06 补同步。

## C03 备注与归档目录分开

账号使用稳定内部 ID。修改备注只改变显示名称，不自动重命名归档文件夹、不移动历史文件，也不修改现有微信链接。

命令行列表同时显示备注和实际归档位置，避免用户把修改备注理解为文件夹已经改名。文件夹名称在账号添加时确定并独立保存，重名与路径冲突安全避让。

## C04 移除与恢复账号

移除账号保留实体、链接、历史基线和同步记录，清除当前配置及未完成操作中保存的源书签并停止管理。恢复时必须显式选择原账号、重新授权并核对目录身份，复用原账号 ID 和基线，不从历史备份自动恢复授权。

## C05 升级保留原文件位置

M1 升级后，已有文件与链接不搬动，原目标相对路径不改写。旧配置迁移为一个“原账号”，之后的新文件进入独立账号子目录。旧数据库备份只作为升级前快照，不能代替最新状态。

## C06 恢复后补同步

暂停期间新增且仍在源目录中的文件，在恢复后重新进行稳定观察并补同步。暂停和恢复不重建历史基线，不把暂停期间的新增文件标成启用前历史文件。

## 既有规则继续适用

管理根目录可配置，下载仅为默认建议。账号的初始归档子目录与整个管理根目录的跟踪范围分开；用户在范围内移动文件不改变源账号。内容去重仍限定于账号内，并在 M3 实现。

测试继续使用临时样本、假授权数据和可注入的访问结果，不操作真实微信文件、真实应用配置或真实登录项。开发分支按实际功能命名。
