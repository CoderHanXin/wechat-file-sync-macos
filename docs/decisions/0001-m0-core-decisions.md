# M0 核心决策

日期：2026-11-18。状态：以下决定已由用户确认，作为 M1 及后续阶段的实施依据。

2026-11-19 补充：删除与恢复细节以 [M4 简化决定](0004-file-association-recovery.md) 为准：原身份返回自动恢复程序清理的链接，副本由用户指定并预览确认，必要记录长期保留，历史清理暂缓。其余原始决定继续有效。

## 账号与内容

同一账号内按内容去重，账号之间独立保存。一个实体文件可以关联同一账号的多个微信源路径；删除、权限和外部编辑的影响范围以该实体的全部来源为准。多账号管理在 M2 实现，内容合并在 M3 实现。

## 可配置的管理根目录

管理根目录是用户授权、允许保存文件并跟踪改名和移动的目录。下载目录仅为默认建议值，核心模型、存储字段和路径校验不依赖其名称或固定位置。后续设置允许用户选择自定义目录，并保存相应安全范围书签。

每个账号的初始归档目录位于管理根目录内；跟踪范围覆盖整个管理根目录。文件在范围内移动不改变源账号。移出范围后保留失联记录，并允许用户手动重新定位；不能把“范围内找不到”直接等同于永久删除。

M1 先消除核心中的下载目录假设，并以任意临时目录验证；自定义目录的图形设置、重新授权和根目录变更流程在 M5 完成。单次跨文件系统移动仍不在当前实现范围内。

## 删除与恢复

不隐藏保留完整文件副本。保留恢复所需的关联记录，用户重新指定可访问文件后校验并恢复适用的链接。微信侧清理不反向删除已归档实体。关联记录保留期限、重新收到相同内容后的旧来源复用规则在 M4 细化。

## 只读保护

默认开启，设置变更影响后续文件；已有文件单独显式应用。普通只读用于防误改，不承诺不可覆盖。关闭保护或外部修改后，内容摘要必须重新校验。工具不提供创建可编辑副本、文件编辑和版本管理。M3 实现权限策略，M5 提供设置入口。

## 应用生命周期

采用菜单栏与引擎同进程。关闭配置窗口继续同步，退出应用停止同步。M5 和 M6 实现该行为及登录启动；M1 保留当前命令行后台运行和安装脚本，以免提前改变部署模式。

## SQLite 状态存储

使用系统 SQLite，通过 Swift 的 SQLite3 模块访问，不引入网络下载依赖。数据库统一保存配置、历史基线和同步记录，以事务提交关联变更；文件系统移动与链接切换另有持久化阶段，SQLite 事务不能代替文件操作恢复。

M1 使用版本化的单账号数据库结构，保留状态存储接口，后续通过数据库迁移加入账号、实体与多来源关系。旧 `state.json` 只作为导入源：成功导入后保留原文件，不在数据库损坏或格式不支持时自动回退旧 JSON、重建空状态或重放过期操作。

一个应用实例持有写入锁后再加载或迁移状态。配置授权与目录核对先完成，验证失败不能覆盖原有效书签。M2 再完善多账号配置提交。

## M1 范围

拆分领域模型、文件系统操作、状态存储、单账号引擎、授权配置、后台运行和自测；修复已复现的关联错误与异常阻塞，复用每轮目录索引，并补齐独立回归测试。

M1 不提前实现多账号 GUI、内容去重、只读开关或手动恢复界面。相关规则已经确定，但实现状态必须与各阶段交付一致。具体账号命名、外部编辑展示、应用标识和旧应用导入策略在使用它们的阶段前细化，不阻塞核心重构。
