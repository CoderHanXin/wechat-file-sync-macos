# 状态迁移说明

更新日期：2026-11-18。适用于 M1 单账号核心重构分支。多账号和应用标识变更的完整迁移在后续阶段补充。

## 数据位置与格式

数据仍位于当前应用容器中的应用支持目录 `WeChatDownloadSync`。新状态文件为 `state.sqlite`，保存目录路径与身份、历史基线、同步记录和两个安全范围书签。数据库版本由 SQLite 的 `user_version` 管理，M1 为 1。

从旧版导入时读取 `state.json`、`source.bookmark` 和 `downloads.bookmark`。旧字段 `downloads` 和 `downloadsIdentity` 映射为通用的 `managedRoot` 与 `managedRootIdentity`；导入不移动归档文件，不更改微信已有链接。

## 导入与锁定

配置流程或正常后台启动先取得同一 `sync.lock` 写入锁，再打开数据库。无已提交配置且存在旧 JSON 时，在一个 SQLite 事务内导入状态与现有书签。中断或失败不得产生部分配置。

成功后保留旧文件原样，以后以 SQLite 为准，不重复导入已经过期的 JSON。旧 JSON 是导入前快照，不是持续备份。

JSON 无法解析、书签缺失一半、数据库损坏或版本不支持时，报告错误并保留原文件。已有数据库异常时，不回退旧 JSON、不清空基线、不重建空配置继续同步。

M1 的初次配置允许选择任意合法管理根目录，下载仅为默认建议。对已有配置重新选择不同源目录或不同管理根目录时，拒绝更新并保留原授权；根目录变更和迁移设置在后续界面阶段完成。源目录和管理根目录必须位于同一文件系统，且不能相同或互相包含。

## 诊断与回退

`--check` 和 `--diagnose` 使用已存在数据库的只读连接读取状态，不迁移旧格式，也不争用同步写入锁。旧版只有 JSON 时，先由正常启动或配置完成导入，再使用诊断命令。`--diagnose` 仍会在已授权目录创建并清理独立的临时测试文件。

回退旧程序前应先停止当前同步、备份整个应用支持目录，并核对实际文件与来源。不能直接把保留的旧 JSON 当成新状态使用：迁移后发生的改名、删除和新同步都不在旧快照中。

数据库备份应在应用停止时复制数据库及可能存在的日志文件，或使用 SQLite 备份机制；运行中随意复制单个数据库文件不能代替一致性备份。

## 验证范围

自动测试覆盖旧字段导入、书签与状态一致提交、再次打开不重放旧快照、数据库损坏和版本不支持时保留数据，以及读取诊断连接不能保存状态。真实安全范围书签与旧版安装到新版的桌面流程仍需后续实机验收。
